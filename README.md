# Калькулятор окупаемости недвижимости с автообновлением данных

В этой папке готовый сайт и всё, что нужно, чтобы данные на нём обновлялись сами. Скрипт раз в сутки берёт у Банка России актуальную ключевую ставку, читает вашу базу программ банков (`baza-bankov.xlsx`) и собирает всё в файл `data/market.json`. Страница `index.html` читает этот файл: показывает ставку ЦБ и подбирает программы банков под введённые цифры. Править сайт при обновлении данных не нужно.

## Три сценария на сайте

1. **Купить и сдавать**: хватит ли аренды на платёж, сколько денег нужно на старте, при какой цене, взносе, аренде или ставке объект выходит в ноль, сравнение с вкладом.
2. **Для своего дела**: что дешевле, купить в кредит или снимать такое же помещение.
3. **Сколько мне потянуть**: максимальная цена объекта по вашим деньгам и комфортному платежу, с переходом в первый сценарий.

Типы объектов: жильё, коммерческая недвижимость (магазин и офис, склад и ангар, производство) и гараж. Для квартир программ банков в базе пока нет, поэтому подбор покажет пустой список.

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html` | сайт с калькулятором, один файл |
| `update_data.py` | скрипт обновления данных |

## Вариант А. Автозапуск на GitHub (бесплатно, свой сервер не нужен)

1. Зарегистрируйтесь на github.com и создайте новый репозиторий.
2. Загрузите в него все файлы из этой папки, включая скрытую папку `.github`.
3. В репозитории откройте **Settings → Actions → General → Workflow permissions**, выберите **Read and write permissions** и сохраните.
4. Откройте вкладку **Actions**, выберите «Обновить данные рынка» и нажмите **Run workflow**.
5. Откройте **Settings → Pages**, в поле **Source** выберите **GitHub Actions**, затем ещё раз запустите «Обновить данные и опубликовать сайт» во вкладке Actions.
6. Через пару минут GitHub покажет адрес сайта (вида `https://ваш-логин.github.io/название-репозитория/`). Данные и сайт дальше обновляются сами: каждый день в 07:00 по Москве и после каждой загрузки новой версии `baza-bankov.xlsx` или `index.html`.

Бесплатный тариф GitHub Pages для приватных репозиториев может быть недоступен. Если Pages не включается, сделайте репозиторий публичным: в нём нет ничего секретного, только ваша база условий банков.

Важно: сервер GitHub находится за границей, а сайт ЦБ может не отвечать на такие запросы. Проверить это можно только запуском. Если в журнале нет ни одного источника, а в `market.json` у `key_rate` стоит `"status": "stale"` или `"missing"`, используйте вариант Б.

Ещё одно замечание: GitHub может отключить автозапуск в репозитории, где долго нет никакой активности. Раз в пару месяцев заглядывайте во вкладку Actions и проверяйте, что запуски идут. Если запуски встанут, страница сама покажет предупреждение о старых данных.

## Вариант Б. Свой сервер в России

Подойдёт любой недорогой VPS с Python 3.8 или новее. Папку с файлами нужно отдавать через любой веб-сервер (например, nginx), `index.html` и папка `data` должны лежать рядом.

```bash
pip install -r requirements.txt
python update_data.py                 # проверить вручную
crontab -e                            # и добавить строку ниже
0 7 * * * cd /путь/к/папке && python3 update_data.py
```

## Как обновлять условия банков

Откройте `baza-bankov.xlsx`, поправьте или добавьте строки на листе «Программы», обязательно укажите ссылку на источник и дату проверки. Загрузите файл в репозиторий (или положите на сервер). `market.json` пересоберётся сам. Строки старше 14 дней скрипт помечает как устаревшие (`"stale": true`), а пропуски (нет ставки, ссылки или даты) выводит в список `warnings`.

## Как устроена ключевая ставка и почему ей можно верить

У ставки три разные даты, и сайт показывает каждую отдельно:

- **Действует с** (`effective_since`): когда ставку изменили в последний раз. Если ЦБ сохраняет ставку, эта дата не меняется месяцами, и это нормально.
- **Проверено** (`confirmed_at`): когда скрипт последний раз подтвердил значение по данным ЦБ. Именно по ней судят о свежести.
- **Заседание** (`last_meeting`): итог последнего заседания, например «23.10.2026: ставка сохранена». Показывается только если его удалось прочитать в этом запуске.

Защита от устаревших данных состоит из четырёх слоёв:

1. **Три источника.** Скрипт спрашивает ЦБ тремя способами: веб-сервис DailyInfo, таблица ключевой ставки на cbr.ru и страница пресс-релизов. Хватает одного успешного. Если два источника дали разные значения, ставка помечается как спорная, и сайт просит сверить её на cbr.ru.
2. **Свежесть считает браузер.** Страница сравнивает дату подтверждения с сегодняшним днём в момент открытия, а не читает готовый статус из файла. Если ежедневное обновление встанет, через 3 дня страница сама покажет предупреждение. Так же считаются метки «данные могли устареть» у программ банков (порог 14 дней).
3. **Громкий сбой.** Если ставка не подтверждена свежо, последнее задание автозапуска завершается ошибкой, и GitHub присылает письмо о неудачном запуске (если у вас включены уведомления). Сайт при этом всё равно публикуется.
4. **Тесты на этот случай.** Есть проверка на сценарий «ставку не меняли три месяца, подтвердили сегодня»: такая ставка считается свежей.

Проверить свежесть вручную: `python update_data.py --check` (код возврата 1, если что-то не так).

Что здесь проверено, а что нет: веб-сервис DailyInfo описан на сайте ЦБ, остальные два источника я писал по описанию страниц, и из своей среды открыть сайт ЦБ напрямую не мог. Разбор страниц проверен на образцах, составленных по описанию, а не на настоящих страницах. Поэтому после первого запуска откройте журнал шага «Обновить data/market.json»: там будет строка «источники: ...» со списком тех, что ответили. Если там нет ни одного, разбор подгонять нужно по реальному ответу.

## Что в market.json

- `key_rate`: `value_pct`, `effective_since`, `confirmed_at`, `last_meeting`, `sources` (кто подтвердил в этом запуске) и `status`: `ok`, `stale` (подтверждение старше 3 дней), `conflict` (источники расходятся), `missing` (данных нет).
- `summary`: число программ, сколько устарело, минимальная ставка и её отрыв от ключевой в процентных пунктах.
- `programs`: все программы из базы с возрастом данных.
- `warnings`: что стоит исправить.

```bash
python -m unittest discover -s tests
```

## Сверка ставок банков с источниками

Раз в сутки `verify_sources.py` открывает страницу-источник каждой программы (сейчас читаются только страницы `ru.myfin.by`) и проверяет, что ставка из базы всё ещё на ней стоит. Скрипт ничего не подставляет в базу, он только записывает результат в `data/verification.json`:

- **ok**: ставка совпала, программа считается проверенной сегодня и на сайте подписана «Сверено с источником».
- **changed**: на странице другая ставка. Программа помечается устаревшей, на сайте видна ставка с источника, а в `warnings` попадает напоминание обновить базу.
- **unreadable**: страницу не удалось прочитать или ставки в тексте нет. Дата проверки не обновляется.
- **blocked**: `robots.txt` запрещает чтение. **unsupported**: источник не из `ru.myfin.by` (сейчас это Сбербанк «Коммерческая ипотека» и Банк «Санкт-Петербург»).

Скрипт выдерживает паузу 3 секунды между запросами, представляется в заголовке запроса и не читает страницы без разрешения `robots.txt`. Условия myfin.by не запрещают автоматическое чтение и требуют активной ссылки на источник при републикации: ссылка есть в каждой карточке. Если правила изменятся, отключите шаг «Сверить ставки с источниками» в `.github/workflows/update.yml`.

**Что проверено, а что нет.** Логика разбора проверена тестами на образцах страниц, которые я составил сам. Настоящую страницу из моей среды открыть нельзя, поэтому после первого запуска откройте журнал шага «Сверить ставки с источниками»: там будет строка «Сверка источников: ok: N, ...». Если почти везде `unreadable`, значит страница отдаёт ставку не в тексте (например, рисует её скриптом), и разбор нужно подгонять по реальному ответу. Сайт при этом не ломается: программы просто станут помечаться устаревшими через 14 дней.

Сверка видит только изменение ставки «от». Изменение взноса, срока, суммы и условий она не заметит, их по-прежнему проверяют вручную.

## Чего скрипт не делает

Он не собирает ставки банков сам. Открытого источника с условиями всех банков нет: ВТБ и ДОМ.РФ запрещают роботам читать свои страницы, а агрегаторы отдают данные по договорам. Когда у вас появится доступ к API (партнёрская сеть, ДОМ.РФ Банк, Сравни), добавьте функцию загрузки рядом с `src_soap` в `update_data.py`, остальное подхватится.

## Как на сайте зарабатывать

Сайт задуман для людей, которые разбираются в теме: инвесторов, собственников бизнеса, тех, кто сравнивает объекты. Заработок строится на трафике и заявках, а не на подписке с первого дня.

1. **Партнёрские ссылки банков.** В `index.html` есть объект `PARTNERS`: впишите ссылку партнёрской программы рядом с названием банка, и в его карточке появится кнопка «Подать заявку» и пометка «Партнёр». Порядок в списке от этого не меняется, он считается по расчёту. Реклама должна быть маркирована по закону, поэтому ссылки берите из партнёрских сетей, которые выдают токен `erid`.
2. **Заявки для брокеров и оценщиков.** Люди, дошедшие до решения о покупке, платные лиды для кредитных брокеров, оценщиков и юристов по сделкам. Для этого нужна форма, а при сборе имён и телефонов — соблюдение закона о персональных данных (152-ФЗ). Без этого форму не добавляйте.
3. **Платный разбор объектов.** Расчёт в PDF и разбор конкретного объекта вручную.

Для получения денег нужен статус самозанятого или ИП и договор с партнёром. Это шаги, которые я сделать за вас не могу.
